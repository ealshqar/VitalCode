## سيناريو 1: فحص آلي كامل

### 📋 الخطوات من منظور المستخدم

```
1. الفاحص يفتح التطبيق Vital Expert
2. يختار المريض من القائمة
3. ينقر على "Auto Test" أو "Automated Test"
4. تظهر شاشة XtraFormAutoTest
5. النظام يتصل بالأجهزة تلقائياً
6. الفاحص ينقر "Start Automation"
7. النظام يجري الفحوصات الأولية
8. يبدأ المسح التلقائي للنقاط
9. عرض النتائج بعد كل نقطة
10. عند الانتهاء، مرحلة الجرعات
11. تحديد المنتجات والكميات
12. طباعة التقرير
```

## 4. التدفق التقني التفصيلي

### 4.1 قراءة واحدة - من البداية للنهاية

```
┌─────────────────────────────────────────────────────┐
│  المستخدم يضع أدوات CSA على جسم المريض               │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  CSA Device يقيس المقاومة الكهربائية                 │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  CSA يرسل البيانات عبر Serial Port                   │
│  Format: Hexadecimal (2 bytes)                      │
│  Example: 0x00FF                                    │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  HwCommunicationHelper                              │
│  - استقبال عبر DataReceived Event                   │
│  - قراءة Bytes من Serial Port                      │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  ProcessReceivedData(hexData)                       │
│  1. تحويل "00FF" → 255                             │
│  2. البحث في ValueTranslate Array                  │
│  3. حساب القراءة الفعلية: index/2 = 127            │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  InvokeReadingReceivedEvent(127)                    │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  Repository Layer                                   │
│  - ReadingReceivedHandler(127)                      │
│  - تحديث _currentReading                            │
│  - حساب Min/Max                                     │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  التحقق من MinimumReadingtoRegister                 │
│  if (127 >= 46) → متابعة                            │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  MeterValueChanged Event                            │
│  - إطلاق الحدث: (sender, 127, 120, 130)            │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  Manager Layer                                      │
│  - manager.MeterValueChanged Handler                │
│  - تحديث CurrentReading Model                       │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  التحقق من الاستقرار (Stability Check)              │
│  - هل الفرق < ReadingStabilityRange (5)؟           │
│  - هل مرّ الوقت > ReadingStabilityTimeout (1000ms)؟│
│  - هل عدد القراءات المستقرة >= 3؟                   │
└────────────────────┬────────────────────────────────┘
                     │
                     ├─ نعم (مستقرة)
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  ReadingStabled Event                               │
│  - إطلاق: (sender, 127, 120, 130, fall, rise)      │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
│  UI Layer Handler                                   │
│  - التحقق من InvokeRequired                         │
│  - استخدام Invoke للـ Main Thread                  │
└────────────────────┬────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────┐
```

## 5. حالات خاصة

### 5.1 Multi-Level Scanning (المسح متعدد المستويات)

```
السيناريو: فحص فئة منتجات (Product Category) بها 50 منتج

الطريقة: Elimination Scanning (المسح بالحذف)

الجولة 1: فحص المجموعة الكاملة (50 عنصر)
├─→ القراءة: 75
└─→ القرار: تقسيم (Split)

الجولة 2: فحص النصف الأول (25 عنصر)
├─→ القراءة: 80
└─→ القرار: هذا النصف فيه مشكلة

الجولة 3: فحص النصف الأول من النصف (12-13 عنصر)
├─→ القراءة: 78
└─→ القرار: تقسيم مرة أخرى

الجولة 4: فحص ربع المجموعة (6-7 عناصر)
├─→ القراءة: 82
└─→ القرار: تقسيم

الجولة 5: فحص 3-4 عناصر
├─→ القراءة: 85
└─→ القرار: تقسيم

الجولة 6: فحص عنصر واحد في كل مرة
├─→ العنصر A: 85 → مشكلة ✓
├─→ العنصر B: 50 → سليم
└─→ النتيجة: العنصر A هو المشكلة
```

**الكود**:

```csharp
private void ProcessMultiLevelScanning(List<AutoItem> items, int depth = 0)
{
    if (items.Count == 1)
    {
        // وصلنا للعنصر الواحد
        MarkAsResult(items[0]);
        return;
    }
    
    // فحص المجموعة الحالية
    var reading = PerformGroupReading(items);
    
    if (reading >= 55)  // قراءة عالية = مشكلة
    {
        // تقسيم المجموعة
        var half = items.Count / 2;
        var firstHalf = items.Take(half).ToList();
        var secondHalf = items.Skip(half).ToList();
        
        // فحص النصف الأول
        var firstReading = PerformGroupReading(firstHalf);
        
        if (firstReading >= 55)
        {
            // المشكلة في النصف الأول
            ProcessMultiLevelScanning(firstHalf, depth + 1);
        }
        else
        {
            // المشكلة في النصف الثاني
            ProcessMultiLevelScanning(secondHalf, depth + 1);
        }
    }
    else
    {
        // المجموعة سليمة، لا حاجة للتقسيم
        return;
    }
}
```

## 6. الخلاصة والنقاط الرئيسية

### مسار البيانات الكامل

```
Medical Device (الجهاز الطبي)
    ↓ قياس فيزيائي
Serial Port (منفذ تسلسلي)
    ↓ بيانات Hex
HwCommunicationHelper
    ↓ معالجة وتحويل
Hardware Repository
    ↓ حدث مع بيانات
Business Manager
    ↓ منطق ومعالجة
UI Form
    ↓ Invoke للـ UI Thread
User Interface
    ↓ عرض للمستخدم
Database
    ↓ حفظ دائم
```

### الوقت المتوقع لكل خطوة

```
الاتصال الأولي:     2-5 ثواني
فحص واحد (نقطة):    2-4 ثواني
  ├─ SetPoint:       200ms
  ├─ StartReading:   100ms
  ├─ انتظار استقرار: 1-3 ثواني
  └─ حفظ:           200ms

فحص كامل (50 نقطة): 2-4 دقيقة
  ├─ الفحوصات الأولية: 30 ثانية
  ├─ المسح: 100-150 ثانية
  └─ الجرعات: 2-5 دقائق (يدوي)

Total: 5-10 دقائق (حسب عدد النقاط)
```

### النقاط الحرجة

⚠️ **Thread Safety**: كل تحديث UI يجب أن يستخدم Invoke  
⚠️ **Memory Management**: إلغاء الاشتراك في الأحداث ضروري  
⚠️ **Error Recovery**: معالجة انقطاع الاتصال أثناء الفحص  
⚠️ **Data Integrity**: حفظ Bookmarks قبل أي عملية خطرة  
⚠️ **Timeouts**: قد تحتاج زيادة للأجهزة البطيئة
